# 从自己的源码编译 → 本地安装 → 从自己的 GitHub 自动更新

> 适用于 `wodeya163/solidcraft`。目标：**不下载上游任何安装包**，程序由本仓库源码编译，
> 装到本机后，程序内「检查更新」查的、下载的、校验的全是 `wodeya163/solidcraft` 自己的 Release。

## 一、为什么必须重新编译

上游二进制里 `crates/ui-egui/src/update.rs` 的更新地址是编译期常量，改配置文件改不动它。
只替换语言包/改注册表，程序仍然会去 `tangency-labs/solidcraft` 检查更新。所以本方案在源码层改死：

| 文件 | 改动 | 作用 |
|---|---|---|
| `crates/ui-egui/src/update.rs` | `REPO` / `LATEST_API` / `RELEASES_PAGE` → `wodeya163/solidcraft` | 检查更新、下载、发行页全部指向自己的仓库 |
| `crates/ui-egui/src/update.rs` | `RELEASE_PREFIXES` 增加 `wodeya163` 前缀（保留两个上游前缀兼容旧数据） | GitHub 返回的资产 URL 才不会被当成不可信而丢弃 |
| `crates/ui-egui/src/update.rs` | `release_notes_url` 的 `HISTORY` → 自己的 releases | 版本说明链接指向自己的 Release |
| `crates/ui-egui/src/prefs/fields/general.rs` | 默认语言 `system` → `zh` | 首启即简体中文，设置里仍可改回 |
| `fonts.rs` / `i18n.rs` / `update/tests.rs` | 同步断言与测试 | 保持测试一致 |

**本机没有 Rust/MSVC 也能做**：编译放在 GitHub Actions 的 `windows-latest` 上，云端内网上传 Release 资产，
绕开本机上行限速。工作流：`.github/workflows/build-from-source.yml`。

## 二、代码怎么进 GitHub

工作区源码目录 `solidcraft-main/solidcraft-main/` 已建成本地 git 仓库并推送到分支
`source-v0.49.0`（保留 `main` 与既有 Release `v0.48.2` 不动）。推送用的是「接上远程 main 的提交历史 +
只发差异对象」的方式，不需要把 270MB 源码整个重传。

## 三、触发云端编译与发布

1. 打开 `https://github.com/wodeya163/solidcraft/actions/workflows/build-from-source.yml`
2. 点「Run workflow」，分支选 `source-v0.49.0`，`version` 填 **与根 `Cargo.toml` 一致**的版本（当前 `0.49.0`），勾选 `publish`
3. 工作流依次做：装 Rust 1.99.1 (MSVC x64) → 装 WiX v5 / NSIS → `cargo build` 主程序与 CLI（静态 CRT）
   → 中文 MSI/便携包 → 单文件 exe → NSIS 中文安装向导 → 生成 `SHA256SUMS.txt` / `latest.json`
   → 发布到 `releases/latest`

也可命令行触发：

```bash
gh workflow run build-from-source.yml \
  --repo wodeya163/solidcraft --ref source-v0.49.0 \
  -f version=0.49.0 -f publish=true
```

> 版本号必须与 `Cargo.toml` 的 `[workspace.package] version` 一致，工作流会先核对，不一致直接失败。
> 因为 `asset_name()` 给单文件 exe 拼的是带版本号的
> `SolidCraft-<版本>-windows-x64.exe`，版本号错了更新器就找不到资产。

## 四、本地安装（免管理员，绕开 msiexec）

下载 Release 的 **`SolidCraft-0.49.0-zh-cn-setup.exe`**，双击：

- 中文安装向导，默认装到 `%LOCALAPPDATA%\Programs\SolidCraft中文版`，**不需要管理员权限**
- 建开始菜单「SolidCraft 中文版」「检查更新」、桌面快捷方式，写 HKCU 卸载项
- 安装目录里同时放 `solidcraft-cli.exe` —— 这决定内置更新器把它判为「便携安装」形态
- 不要手工装到 `C:\Program Files\...`，那样会被判为 MSI 形态（也能更新，但会走 MSI 通道）

其它可选产物：

| 产物 | 用途 |
|---|---|
| `SolidCraft-0.49.0-windows-x64.exe` | 单文件免安装，双击直接跑；更新器按同名格式替换自身 |
| `solidcraft-windows-x64.msi` | 稳定名 MSI，适合 IT 批量部署（需管理员 / msiexec） |
| `solidcraft-windows-x64-portable.zip` | 稳定名便携包，内置更新器自动下载它替换 exe + CLI |
| `SHA256SUMS.txt` | **必须发布**，更新器下载资产后按它校验，缺失或没列资产名会拒绝更新 |
| `latest.json` | 中文更新清单（人读 / 随包中文更新器用），内置更新器直接查 GitHub API |

## 五、自动更新链路与验收

程序启动时会（且每天一次）请求：

```
https://api.github.com/repos/wodeya163/solidcraft/releases/latest
```

按安装形态选择资产名，下载后用同一 Release 的 `SHA256SUMS.txt` 校验，再原地替换并重启：

| 安装形态 | 判定条件 | 下载的资产 |
|---|---|---|
| `WindowsMsi` | exe 在 Program Files 或 HKLM 记录了 InstallDir | `solidcraft-windows-x64.msi` |
| `WindowsPortable` | 同目录有 `solidcraft-cli.exe`（**NSIS 安装器属于这类**） | `solidcraft-windows-x64-portable.zip` |
| `WindowsExe` | 单文件、同目录没有 CLI | `SolidCraft-<版本>-windows-x64.exe` |

**验收清单**

1. 首次启动界面为简体中文（右上角设置 → 常规 → 语言显示「简体中文」）
2. 帮助 → 检查更新：网络请求指向 `api.github.com/repos/wodeya163/solidcraft/...`，不出现 `tangency-labs`
3. 当前版本与 Release 一致时提示「已是最新版本」
4. 发一个更高版本（改 `Cargo.toml` → 触发工作流 → tag `v0.49.1`）后，程序能提示新版本并自动下载升级
5. Release 的 `SHA256SUMS.txt` 列出了上述三个资产名，哈希与实际文件一致

## 六、发新版流程

1. 改根 `Cargo.toml` 的 `[workspace.package] version`（如 `0.49.1`），同步 `Cargo.lock`
2. 提交推送到 `source-v0.49.0`
3. 触发 `build-from-source.yml`，`version=0.49.1`、`publish=true`
4. 工作流创建 `v0.49.1` 并标为 latest；所有已安装程序下一次检查更新即可升级

## 七、常见问题

- **更新器提示"没有可用更新"但 Release 已有新版**：确认 Release 非 draft、非 prerelease，
  且 `tag_name` 是 `v<版本>`；`is_newer()` 按 semver 比较。
- **提示 `SHA256SUMS.txt doesn't list <资产名>`**：编译/打包后必须跑
  `build-from-source.ps1` 第 5 步重新生成校验表，确保资产名逐字一致。
- **NSIS 安装后更新走 MSI 通道**：安装目录被选到了 Program Files；改装到用户目录即可。
- **想在本机自己编译**：装 Rust 1.99.1 (MSVC x64) + VS 2022 生成工具 + WiX v5 + NSIS，
  然后 `pwsh zh-cn/packaging/windows/build-from-source.ps1 -Version 0.49.0`。
  产物在 `dist/release/`，但上传大文件到 Release 建议仍走云端工作流。
